# Video script: Capstone: your first external contribution

Target length: about 2 minutes.

## Scene 1: Hook
visual: slide
title: Now do it for real
bullets:
- A merged PR in a project you don't own
- Then join the graduates wall
- A bot checks it on GitHub

> This is it. Everything in the course leads here: a merged pull request in
> a real open source project that you don't own. When it's merged, you add
> yourself to the graduates wall, and a bot checks your pull request on
> GitHub before letting you in.

## Scene 2: What counts
visual: slide
title: What counts
bullets:
- Merged, not just opened
- A real project: not yours, not a fork, not a practice repo
- Opened by you, merged by a maintainer
- Code, tests or docs: all count

> Here's what counts. It has to be merged, not just opened. In a real
> project: not your own, not a fork, and not a practice repository like this
> one. You opened it, and a maintainer merged it. And code, tests or
> documentation all count equally.

## Scene 3: What doesn't
visual: slide
title: Would they have wanted it anyway?
bullets:
- Not whitespace-only changes
- Not "fixes" that aren't errors
- Not anything opened just to tick a box

> What doesn't count, even if it somehow gets merged: whitespace changes,
> spelling fixes that weren't mistakes, anything opened just to tick a box.
> Maintainers can tell, and it costs them time. Ask yourself: would the
> maintainer have wanted this change even if you weren't doing a course?

## Scene 4: Stage by stage
visual: slide
title: The capstone, stage by stage
bullets:
- Choose: lesson 7
- House rules: lesson 5
- Set up and test: lesson 6
- Change: lesson 8. Review: lesson 9. Wait: lesson 11

> The written lesson has a checklist for every stage, each linked to the
> lesson that taught it. Choose an issue and do the five checks. Read the
> house rules. Set up, and get the tests passing before you change anything.
> Make the smallest good change. Open the pull request, handle review, and
> wait patiently.

## Scene 5: Start small
visual: slide
title: Start small
bullets:
- A docs fix or small bug is a great capstone
- Expect 1 to 4 weeks, mostly waiting
- Start a second candidate while you wait

> Start small. A documentation fix or a small bug is a perfect capstone.
> Expect it to take one to four weeks, mostly waiting for review. While you
> wait, it's fine to start on a second candidate somewhere else.

## Scene 6: Graduate
visual: code
code:
```
name = "Ada Lovelace"
github = "ada"
pr = "https://github.com/OWNER/REPO/pull/123"
message = "One sentence: what you changed, or what you learned"
```

> When it's merged, come back to this course repository. Make a branch, and
> add a file in the graduates folder, named after your username, with your
> name, your username, the link to your merged pull request, and one
> sentence about it. Then open a pull request, just like lesson four.

## Scene 7: The bot
visual: slide
title: The graduate bot checks
bullets:
- Merged, and opened by you
- Merged by a maintainer, not you
- A real project you don't own
- Then 🎓, merge, and the wall

> The bot looks up your pull request on GitHub. Merged, opened by you,
> merged by a maintainer, in a real project you don't own. If it all checks
> out, it congratulates you, merges, and adds you to the graduates wall.

## Scene 8: Welcome
visual: slide
title: Welcome to open source
bullets:
- Go back to the same project
- Help the next beginner
- You can contribute anywhere now

> And then: welcome to open source. Go back to the same project, because
> your second pull request will be much easier. Help the next beginner who's
> where you were a few weeks ago. You can contribute to any project now.
> Thank you for taking the course.
